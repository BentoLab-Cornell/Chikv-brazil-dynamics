# Data and generated-file inventory

The source inventory below is verified from the repository tree at upstream commit `453a4217e677171baa7af4492e1fbeb3fd46bfbe`. Packaging changes leave these source files in place. Presence is distinct from provenance or validation of their scientific construction.

## Included source files

| Location | Files | Use in the revised paper |
|---|---|---|
| `chikungunya/` | 12 DBC files, `CHIKBR15.dbc` through `CHIKBR26.dbc` | 2016–2025 files feed the primary import; 2026 is separate temporal evaluation; 2015 is retained but excluded from the revised study window |
| `population/` | 11 CSVs, `ibge_pop_age_2015_clean.csv` through `ibge_pop_age_2025_clean.csv` | Module 02 reads 2016–2025; 2015 is retained outside the current panel |
| `zika/` | `zikadata.zip` | Historical archive; not an input to the revised primary chikungunya model |

The population CSVs contain a municipality identifier/name column, age columns from under 1 year through 79 years, an open-ended 80+ category, and `Total`. Module 02 reads the files as Latin-1. Do not overwrite these source files with generated panels.

SINAN/DATASUS and IBGE are the stated source institutions. File names alone do not establish the retrieval date, source release, revision history, or how the cleaned age estimates were constructed. Those records remain to be documented. The CHIKBR26 file is a partial surveillance snapshot; its latest onset date is not a download date.

Geometry and health-region data are requested through `geobr` by the research modules. Corresponding production geometry, crosswalk and retrieval/version metadata are not present as an archived source bundle. Record the actual versions used rather than assuming a current download reproduces them.

## Missing production evidence

No primary/sensitivity fit RDS files, rolling predictions, longer-horizon output bundle, production session lockfile or HPC log bundle was included in the upstream tree. Local generation or later deposition should be accompanied by a manifest recording the exact filename, generating commit, input hashes, model settings, dimensions, keys/order, creation time and relevant source snapshot. Verify which files generated the submitted estimates before treating them as production evidence.

Preserve raw and cleaned inputs separately. Do not silently update the provisional 2026 snapshot, substitute a different population vintage, or mix cached outputs from different municipality definitions while attempting to reproduce an older reported result.
